# Worked example

A self-contained 2-frame, dual-lens dataset to verify a fresh install of `AM_ImageAndMask_to_cubemap_v4.py` produces correct output.

## Scene

Outdoor garden capture from a DJI Osmo 360 (dual fisheye, equisolid). Two frames per lens (`000020`, `000034`). 

## Run

From this `examples/` directory:

```powershell
.\run_example.bat        # Windows
./run_example.sh         # macOS/Linux (chmod +x first)
```

The script processes the back lens first, then the front lens. First-time runtime is roughly **3 minutes per lens** on a modern desktop — the per-face remap computation (5 faces × ~25 seconds each) is the bulk of it. Image processing itself is a few seconds per fisheye frame. After the first run, the per-lens cache under `output/Lens-*/bonusdata/` makes subsequent runs near-instant for the same calibration.

## Verification

After a successful run, `output/` looks like:

```
output/
├── Lens-back/
│   ├── images/
│   │   ├── 000020/                   5 cube face PNGs
│   │   └── 000034/                   5 cube face PNGs
│   ├── masks/                        face masks for both frames (flat)
│   └── bonusdata/                    useful_pixel_mask, RAW geometry, remap cache, visualizations
└── Lens-front/
    └── (same shape)
```

Compare your output against the committed reference:

| Your output | Reference |
|---|---|
| `output/Lens-back/images/000020/000020_dir_plusZ.png` | `expected_output/back/000020_dir_plusZ.png` |
| `output/Lens-back/images/000034/000034_dir_plusZ.png` | `expected_output/back/000034_dir_plusZ.png` |
| `output/Lens-front/images/000020/000020_dir_plusZ.png` | `expected_output/front/000020_dir_plusZ.png` |
| `output/Lens-front/images/000034/000034_dir_plusZ.png` | `expected_output/front/000034_dir_plusZ.png` |

They should be visually identical. Pixel-exact byte matching may differ across OpenCV / numpy versions and platforms; visual equivalence is the verification standard.
